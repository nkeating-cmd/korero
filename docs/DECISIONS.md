# Kōrero: decision log

The one decision log for Kōrero: decisions that change how Kōrero is built, released or behaves, oldest first.
Started 16 Oct 2026. D-001 to D-006 are backfilled from the project record (`KORERO_STATE.md` and the build notes
in the Kōrero claude.ai project), where some carried older labels (shown in brackets); those labels are retired.

- **Status:** `Proposed` (written down, not decided; binds nothing), `Accepted`, `Superseded by D-NNN` or
  `Withdrawn`. The code follows `Accepted` rows only.
- **Adding a row:** it goes in the same PR as the change it records. Take the next free number on `korero/main`
  when the PR is ready to merge, not when drafting.
- **Product order** (what to build next) lives in `docs/PRODUCT.md`, not here.

| D-015 | 2026-11-26 | Accepted | **Kōrero learns mishearings of names from the corrections the user makes in Dictation history, and a sound match never rewrites text by itself.** When a correction is saved, the words replaced are compared with the words put in their place (`learning.rs`, pure and fuzzed). A replacement is counted only when the two sides sound alike, the corrected side reads as a name (a capital inside it, a macron, or a new capital mid-sentence), and it is not an address, a link or a figure. A single word is almost never a rule by itself, because a rule for one word changes every use of it and the heard word may be a real word or another person's name ("minister" to "Ministry", "Tim" to "Tom", "marama" to "mārama"): it takes the unchanged word beside it as context and is learnt as a phrase ("kite today" to "Kyt today"). The one exception is a word whose corrected form has a capital inside it (FENZ, GitHub). Nothing is learnt when every word Kōrero wrote is ordinary English ("mark said", "who is"), when a te reo word's macron-free form is a listed different word (`reo_lexicon::is_ambiguous_bare`: tangata, tāngata), for a possessive or plural of the same word ("Chris" to "Chris's"), or when only first-letter capitals changed. A phrase becomes a rule the second time the same replacement is made and a bare word (FENZ) the third, applied on dictation only (`learning::apply` from `actions::snap_dictation`: whole words, longest rule first, each stretch changed once, never inside an address, web name or hyphenated word), with the words as heard kept as the History entry's original. If the user puts the heard words back where a rule changed them, the rule is switched off and is never learnt again; deleting or rewording the sentence does not count. Learnt pairs are kept apart from taught corrections (`learned_pairs` in settings): they are stored on this computer, reach no meeting, note or import, and are given to no AI as a list, until the user chooses "Use everywhere", which makes one a taught correction. A dictation Kōrero has corrected is still cleaned up like any other when a clean-up is asked for. One switch turns learning off. Nic, 26 Nov: "I want the most automated way … while maintaining the data security"; then "execute, please". | Nic runs Parakeet, which takes no vocabulary (`transcription.rs`: the bias prompt reaches Whisper only), so every fix is made to the text afterwards. "foreign emergency" is 4 letter edits in 16 from "Fire and Emergency" (0.25), over the 0.18 fuzzy threshold, so a custom word could not have fixed it. Red team, 26 Nov, with a standard sound key: "front emergency" and "friend emergency" score 0 from the target, "for an emergency" 1, "foreign emergency" 2, so no threshold separates the mishearing from ordinary English, and "for an emergency" is in Nic's own meetings store. The corrections glossary goes to the notes model, which can be a cloud provider, so an unreviewed pair must not be in it. Costs accepted: a single-word name (Kyt, Nic) is learnt only beside the same neighbouring word twice, so it is learnt more slowly than a phrase, and a taught correction remains the quick way to fix one word everywhere; a name the transcriber already capitalised is learnt only mid-sentence and only when both spellings sound the same ("Nick there" to "Nic there"; never "Tuesday" to "Thursday"); a name whose every heard word is ordinary English is not learnt at all; a phrase rule made from a change of meaning ("minister said" to "Ministry said", made twice) is possible but narrow; the sound test is coarse ("family emergency" passes it), so the name and repeat rules carry the weight; text typed with combining accents is not handled. The settings page can switch a pair off or forget it and cannot add or alter one (`learning::page_edit`). The independent review (26 Nov) found six Major problems in the first version and three more in the second, all fixed and kept as tests (L-022). | Match custom words by sound and rewrite: fails as above (L-020 again). Learn any repeated edit: learns rewording ("costs" to "cost"; the 26 Nov red team's M5). Learn on the first edit: one slip becomes a rule. Put learnt pairs straight into taught corrections: they would reach meetings and cloud prompts unreviewed. Read corrections back from the application pasted into: the only source that sees edits made outside Kōrero, but it reads other applications' text and its coverage is unmeasured; a probe first (B15). | A learnt rule is reported wrong in real use; the B15 probe passes, which adds a second source to the same list; a user wants learnt rules in meetings without a click. |
